# تلبینو (Telebino)

پلتفرم بات‌ساز تلگرام بدون کدنویسی، برای فروشگاه‌های آنلاین، مجموعه‌های آموزشی و مراکز مشاوره‌ی ایرانی.

این پروژه سه بخش مجزا داره که همه در همین ریپو زندگی می‌کنن:

| بخش | مسیر | توضیح |
|---|---|---|
| **فرانت‌اند** (لندینگ + پنل کاربری + پنل ادمین) | `/` (ریشه‌ی پروژه) | Next.js 16 + TypeScript + Tailwind v4 |
| **بک‌اند** (API) | `/api` | NestJS + Prisma + PostgreSQL |
| **دیتابیس** | خارج از ریپو | PostgreSQL محلی (چون Docker روی این سیستم نصب نیست) |

---

## ۱. راه‌اندازی محیط توسعه

### ۱.۱ دیتابیس (PostgreSQL)

چون **Docker روی این سیستم نصب نیست**، یک نمونه‌ی PostgreSQL ایزوله (جدا از هر Postgres دیگه‌ای که ممکنه روی سیستم باشه) به‌صورت دستی راه‌اندازی شده:

- مسیر داده: `~/.telebino-dev/pgdata`
- پورت: `5544` (برای جلوگیری از تداخل با نمونه‌های دیگه)
- نام دیتابیس: `telebino_dev`
- کاربر: `telebino` (بدون رمز — `trust` auth، فقط برای dev)

**روشن کردن دیتابیس** (بعد از ری‌استارت سیستم لازمه، چون خودکار بالا نمیاد):

```bash
/Applications/Postgres.app/Contents/Versions/latest/bin/pg_ctl \
  -D ~/.telebino-dev/pgdata \
  -o "-p 5544 -k /tmp" \
  -l ~/.telebino-dev/pg.log start
```

**خاموش کردن:**

```bash
/Applications/Postgres.app/Contents/Versions/latest/bin/pg_ctl -D ~/.telebino-dev/pgdata stop
```

> وقتی روی سرور واقعی (مثلاً آروان‌کلاود) مستقر بشه، این محدودیت خودش برطرف می‌شه چون اونجا Postgres به‌صورت دائمی و مدیریت‌شده اجرا می‌مونه.

### ۱.۲ بک‌اند (API)

```bash
cd api
npm install
npx prisma migrate dev   # اگر مهاجرت جدیدی اضافه شده باشه
npm run start:dev
```

API روی `http://localhost:4000/api` بالا میاد (پورت از `.env` خونده می‌شه).

### ۱.۳ فرانت‌اند

```bash
npm install
npm run dev
```

فرانت‌اند معمولاً روی `http://localhost:3000` بالا میاد؛ اگه پورت اشغال باشه (مثلاً توسط VS Code) روی `3001` یا پورت بعدی بالا میاد — همیشه توی خروجی ترمینال آدرس دقیق چاپ می‌شه.

## ۲. آدرس‌های سایت (Routes)

فرض بر اینه که فرانت‌اند روی پورت `3001` بالاست؛ اگه پورت دیگه‌ای گرفت، فقط `3001` رو با پورت واقعی عوض کن.

### عمومی
| آدرس | توضیح |
|---|---|
| `http://localhost:3001/` | لندینگ‌پیج |

### پنل کاربری (صاحبان کسب‌وکار)
| آدرس | توضیح |
|---|---|
| `http://localhost:3001/login` | ورود/ثبت‌نام با شماره موبایل |
| `http://localhost:3001/dashboard` | داشبورد اصلی |
| `http://localhost:3001/dashboard/products` | محصولات |
| `http://localhost:3001/dashboard/faq` | سوالات متداول |
| `http://localhost:3001/dashboard/lookup` | سفارش‌ها و دسترسی‌ها |
| `http://localhost:3001/dashboard/customers` | مشتریان |
| `http://localhost:3001/dashboard/forms` | فرم‌ساز |
| `http://localhost:3001/dashboard/bots` | اتصال ربات‌های تلگرام |
| `http://localhost:3001/dashboard/broadcast` | پیام همگانی |
| `http://localhost:3001/dashboard/reports` | گزارش‌ها |
| `http://localhost:3001/dashboard/team` | اعضای تیم |
| `http://localhost:3001/dashboard/subscription` | پلن و اشتراک |

### پنل مدیریت پلتفرم (فقط تلبینو)
| آدرس | توضیح |
|---|---|
| `http://localhost:3001/admin/login` | ورود ادمین |
| `http://localhost:3001/admin` | داشبورد آماری پلتفرم |
| `http://localhost:3001/admin/businesses` | مدیریت همه‌ی کسب‌وکارها (پلن، وضعیت اشتراک) |

### API
| آدرس | توضیح |
|---|---|
| `http://localhost:4000/api` | Base URL بک‌اند |

## ۳. اطلاعات ورود (فقط محیط توسعه)

### ورود صاحب کسب‌وکار
- هر شماره موبایل معتبر ایرانی (مثل `09123456789`)
- کد تایید: همیشه **`12345`** (پیامک واقعی هنوز وصل نشده)
- بار اول یک نام کسب‌وکار هم می‌پرسه

### ورود پنل مدیریت (Admin)
| فیلد | مقدار |
|---|---|
| ایمیل | `admin@telebino.ir` |
| رمز عبور | `Telebino@Dev1` |

> ⚠️ این حساب با اسکریپت `api/scripts/seed-admin.ts` ساخته شده (`npm run seed:admin` داخل `api/`). قبل از هر استقرار واقعی، رمز رو عوض کن یا با متغیرهای محیطی `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` مقدار دیگه‌ای بساز.

## ۴. متغیرهای محیطی

### `api/.env`
```
DATABASE_URL              # اتصال به Postgres محلی
JWT_SECRET                # امضای توکن کاربران کسب‌وکار
JWT_EXPIRES_IN
ADMIN_JWT_SECRET          # امضای توکن ادمین — عمداً کلید جدا از JWT_SECRET
ADMIN_JWT_EXPIRES_IN
OTP_DEV_STATIC_CODE       # کد ثابت OTP برای dev — هرگز در production فعال نشه
NODE_ENV
PORT                      # پورت API (پیش‌فرض 4000)
WEB_ORIGIN                # برای تنظیم CORS
PUBLIC_API_URL            # برای ساخت لینک مطلق فایل‌های آپلودی (عکس محصول و ...)
ARVAN_VIDEO_API_KEY       # اختیاری — اگه خالی باشه، آپلود ویدیوی دوره غیرفعاله (خطای واضح می‌ده)
ARVAN_VIDEO_CHANNEL_ID    # اختیاری — شناسه‌ی یک «کانال» مشترک در آروان ویدیو که از پیش دستی ساخته شده
ARVAN_VIDEO_BASE_URL      # اختیاری — پیش‌فرض https://napi.arvancloud.ir/vod/2.0
```

### `.env.local` (ریشه‌ی پروژه)
```
NEXT_PUBLIC_API_URL       # آدرس API که فرانت‌اند بهش وصل می‌شه
```

## ۵. معماری و تصمیمات کلیدی

- **بک‌اند**: NestJS + Prisma (ORM) + PostgreSQL — با ماژول‌های جدا برای هر بخش (auth، products، faq، lookup، customers، forms، team، subscription، reports، bots، broadcast، admin).
- **فرانت‌اند**: Next.js App Router، فونت فارسی Vazirmatn به‌صورت self-hosted (نه از گوگل فونت، چون از ایران گاهی ناپایداره).
- **احراز هویت دوگانه**: کاربران کسب‌وکار (JWT با `JWT_SECRET`) و ادمین پلتفرم (JWT با `ADMIN_JWT_SECRET` کاملاً جدا) — تست شده که توکن هرکدوم روی مسیرهای اون‌یکی رد می‌شه (401).
- **پاسخ‌گویی ربات بدون AI**: تطبیق فازی متن (کتابخونه‌ی Fuse.js) روی سوالات متداول، به‌جای هوش مصنوعی، برای کنترل هزینه.
- **موتور مشترک «جستجوی شناسه»**: پیگیری سفارش (فروشگاه) و بررسی دسترسی (آموزشی) هر دو از یک مدل داده‌ی مشترک (`LookupEntry`) استفاده می‌کنن.
- **ربات تلگرام**: با کتابخونه‌ی `node-telegram-bot-api` (نسخه‌ی ۲، API مدرن مبتنی بر middleware)، به‌صورت long-polling اجرا می‌شه (نه webhook) — برای سادگی در فاز فعلی.
- **محصول از نوع «دوره آموزشی»**: هر `Product` می‌تونه چند `CourseLesson` (جلسه ویدیویی) داشته باشه — نیازی به یک نوع محصول جدا نیست. ویدیوها روی **آروان ویدیو** (ArvanCloud VOD) آپلود می‌شن. چون درگاه پرداخت هنوز وصل نیست، دسترسی به جلسات فقط با **تأیید دستی «پرداخت شده» توسط صاحب کسب‌وکار** در صفحه‌ی سفارش‌ها فعال می‌شه (`CourseAccess`، بر اساس شناسه‌ی تلگرام مشتری — نه شماره تماس). ربات یک منوی «🎓 دوره‌های من» به مشتریانی که دسترسی دارن نشون می‌ده.

## ۶. محدودیت‌های شناخته‌شده (قبل از استقرار واقعی باید حل بشن)

| مورد | وضعیت فعلی | باید چیکار بشه |
|---|---|---|
| پیامک OTP | کد ثابت `12345` | اتصال به یک درگاه پیامکی ایرانی (کاوه‌نگار/قاصدک) |
| پرداخت | تغییر پلن فقط دستی از پنل ادمین؛ سفارش دوره هم فقط با تأیید دستی «پرداخت شده» فعال می‌شه | اتصال به زرین‌پال |
| اتصال به تلگرام | از این دستگاه فقط با VPN فعال قابل دسترسیه (فیلترینگ ایران) — با VPN تست شده و کار می‌کنه | وقتی روی سرور خارج از ایران مستقر شد، نیازی به VPN نیست |
| Redis | وصل نشده | برای صف پیام همگانی و کش در مقیاس واقعی لازم می‌شه |
| پیام همگانی | ارسال inline (داخل همون درخواست، بدون صف واقعی) | جایگزینی با صف واقعی (BullMQ + Redis) |
| هاست | همه چیز محلیه | طبق تصمیم قبلی: سرویس ربات باید خارج از ایران هاست بشه، وب‌سایت/پنل‌ها می‌تونن هرجا باشن |
| لینک پخش ویدیوی دوره (آروان) | لینک ساده (بدون امضای امنیتی/انقضا) برگردونده می‌شه؛ نام دقیق فیلد JSON پاسخ آروان هم از مستندات قابل تأیید نبود (redirect loop روی docs.arvancloud.ir) و با چند نام محتمل حدس زده می‌شه | وقتی دسترسی واقعی به اکانت/مستندات آروان ویدیو موجود شد: پیاده‌سازی امضای secure link (`secure_link_key`) و تأیید نام دقیق فیلد |
| پردازش ویدیوی دوره | وضعیت هر جلسه (در حال پردازش/آماده) فقط هنگام باز کردن لیست جلسات از آروان استعلام می‌شه (polling دستی، نه webhook) | اتصال به webhook تکمیل پردازش آروان، اگه موجود باشه |
